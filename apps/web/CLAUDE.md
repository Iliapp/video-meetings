@AGENTS.md

# web (Next.js)

Next.js 16 (App Router) + React 19, dev server on `:3000`. `AGENTS.md` is regenerated by `next dev`; don't edit it.

## Commands (in `apps/web`, or `pnpm --filter web <script>`)

`dev`, `build`, `start`, `lint`, `typecheck`, `test:e2e`.

## Environment

Copy `.env.example` to `.env.local`: `NEXT_PUBLIC_API_URL` (default `http://localhost:4000`), `NEXT_PUBLIC_RECORDINGS_MAX_BYTES` and `NEXT_PUBLIC_AVATAR_MAX_BYTES` (keep equal to the api's limits; `next.config.ts` fails the build on non-positive integers), `NEXT_DIST_DIR` (set only by e2e).

## Structure

- `src/app/`: routes `/` (dashboard), `login/`, `register/`, `profile/`, `meetings/[id]/` (meeting + recordings). Each `page.tsx` renders a client component that guards itself.
- `src/components/`: shared UI (`AppHeader`, `UserAvatar`, `AuthLayout`, form fields).
- `src/lib/api/`: `client.ts` is the `fetch` wrapper (`ApiError` with status and the Nest message; network failure = status 0); endpoint functions and types per domain (`auth`, `profile`, `meetings`, `recordings`), re-exported from `index.ts`. `uploadRecording` uses XHR for upload progress.
- Recording URLs are signed and expire: fetch them on Play/Download, and on a player media error fetch new ones once and resume from the last position.
- `src/lib/auth-token.ts`, `use-session.ts`: the token lives in `localStorage` and is decoded client-side (unverified). Auth is client-only; there is no `proxy.ts` because the server can't see `localStorage`. A `401` signs out.
- `src/lib/use-profile.ts`: module-level profile store per tab, so header and pages update after a save without a reload.
- `src/lib/{passwords,recordings,avatars}.ts`: client-side validation mirroring the api's rules and messages; keep them in sync with the api.
- Import alias `@/*` → `src/*`.

## UI and styling

- Tailwind CSS v4 configured in CSS (`globals.css`); there is no `tailwind.config.js`.
- **HeroUI v3**: use the `heroui-react` skill for APIs instead of memory, and prefer HeroUI components over hand-rolled ones. Design decisions go through the `ui-ux-pro-max` skill.
- Use semantic tokens (`bg-accent`, `text-muted`), not raw colors or gradients. `--accent`/`--danger` are overridden in `globals.css` for AA contrast.
- Icons: `@gravity-ui/icons`. `FileTrigger`/`DropZone` come from `react-aria-components` (keep its version in line with HeroUI's); wrap a HeroUI `Button` in `FileTrigger`.
- Fonts: Geist / Geist Mono via `next/font/google`.

## Definition of done for UI changes

Anything visible is not done until:

1. It's tested in the running app with the Playwright MCP at 1440, 1920 and 375 px: interactive states (validation, loading, success, server errors), no horizontal scroll, no console errors.
2. It's reviewed with the `ui-ux-pro-max` checklist (accessibility and contrast, touch targets, responsiveness, typography, spacing, forms and feedback), fixed and re-tested.

Report what was tested and at which widths.

## E2E tests

`pnpm test:e2e [file] [-g "<title>"]`. Needs `pnpm db:up` and Google Chrome (`channel: 'chrome'`, since bundled Chromium doesn't run on macOS 12).

- `playwright.config.ts` starts its own api (:4100) and `next build && next start` web (:3100) with small limits and a short URL TTL (`e2e/env.ts`). Already-running servers on those ports are reused, so stop them after changing code.
- `e2e/fixtures.ts` creates data through the api, signs the browser in via `localStorage` or the login form, and fails a test on any console error not listed in `allowConsoleErrors`. Media and avatar fixtures come from `apps/api/test/fixtures/`. Dates are checked in UTC, `en-US`. Traces of failures go to `test-results/`.

## Conventions

- Default to Server Components; `'use client'` only for state, effects or browser APIs.
- Call the api through env-configured URLs, never hardcoded hosts.
- Validate on the client before sending (no request when invalid), with the api's messages. Match api errors by status or `field`, not by message text.
- Forms whose errors update while typing use `validationBehavior="aria"`: react-aria's default clears errors only on blur, and the layout shift makes the submit click miss.
- After a dialog closes because its trigger disappeared or was disabled, move focus to a sensible element (e.g. the file picker).
